# Better Retiming — Vegas 速度线

![Vegas 速度线演示](docs/screenshot/1.png)

Blender **5.2.1+** 的纯 Python 插件（包名 `seqvel`）：在**视频序列编辑器（VSE）**里给条带拖一条
"速度线"，做 Vegas Pro 式的变速——整段等速、插入速度点、拖点制造加速/减速渐变。
编辑结果写入 **Speed Control 效果条带** 的 `speed_factor` 关键帧，因此渲染、预览、
FFmpeg 导出走同一条原生管线，**不需要打开原生 Retiming 开关**。

## 安装 / 更新

从 [Releases](https://github.com/sefFumyc/Better_Retiming/releases) 下载最新的
`seqvel-<版本>.zip`，然后：

Blender → 编辑 → 偏好设置 → 插件 → 安装 → 选该 zip → 勾选启用。

也可以自行打包，或把 `seqvel/` 目录整个复制到
`%APPDATA%\Blender Foundation\Blender\5.2\scripts\addons\`：

```bash
python tools/build_zip.py          # 产出 dist/seqvel-<版本>.zip
```

> ### 更新后必须让 Blender 重新加载插件
>
> Blender **不会**因为磁盘上的文件变了就重新导入已加载的模块：覆盖安装只换掉磁盘上
> 的代码，当前会话里跑的还是**内存里的旧模块**。症状极具迷惑性——"明明修好了，还是
> 报一模一样的错"。下面三选一即可（都已实测有效）：
>
> 1. 完全退出 Blender 再打开（最稳）；
> 2. 偏好设置里把本插件**取消勾选、再勾上**；
> 3. `F3` 搜索 **Reload Scripts** 执行。
>
> **怎么确认当前跑的是哪一版**：面板最下方常显 `Add-on v1.6.6`（中文模式显示
> `插件 v1.6.6`）。看不到这一行、或版本号不是最新的，就说明内存里还是旧代码。
> 拒绝编辑的提示里也带版本号。

## 使用

**没有"编辑模式"这回事**——任何时刻按住**看得见**的线就能拖（见
`docs/adr/0005-direct-manipulation-no-edit-session.md`）。

1. 打开视频序列编辑器，选中一条视频/图片条带 —— 速度线**立即出现**（默认 1.0x 直线）。
2. 鼠标移到位图上，光标变成指向手指 = 这里能抓；**按住线/方块直接拖**，松手即结束。
3. 松手就把曲线写进 `SPD_<条带名>` 承载条带的关键帧（拖一次、插一次、删一次各写一次，
   也各记一步撤销）。
4. 按在**空白处**一律原样穿透：选择、框选、移动播放头、空格播放从不被打断。

| 操作 | 效果 |
|---|---|
| 按住某段线拖动 | **只挪这一段**（两个端点同步平移）→ 该段等速 |
| 按住尾段延长线拖动 | 只挪末点 |
| 在线段上双击 | 插入速度点（0.45s 内、12px 内的两次连点） |
| 拖方块（速度点） | 上下改速度、左右改时间位置（首点 x 固定） |
| **按住 Ctrl 拖动（任意目标）** | **微调**：速度变化减半（光标挪 0.2x，点只挪 0.1x）；拖点时**冻结帧**（只上下移动）。拖动中随时按住/松开实时切换，切换瞬间不跳变；光标越过条带边界后微调仍继续生效（点停在值域边界）；一次拖动仍是一步撤销 |
| 右键按在方块上 | 弹出点菜单（目前只有「删除点」） |
| 右键按在线上的某一段 | 弹出段菜单：线性 / 平滑 / 快速 / 慢速（当前档打勾） |
| 右键按在尾段延长线或空白处 | 原样交给原生右键菜单（不拦截） |
| 中键 / 滚轮 / 空格 | 拖动期间依然可用（平移、缩放、播放） |
| **`Shift+B`** | **内存预览**：把当前范围真的播一遍装进 VSE 缓存（见下） |
| Ctrl+Z / Ctrl+Shift+Z | 逐动作撤销/重做（拖一次、插一次、删一次各一步） |

### 内存预览（`Shift+B`）

像 Vegas 的 Build Dynamic RAM Preview：**按一下，把当前范围真的播一遍**，播完播放头
回到范围开头，之后你自己播这一段就是顺的。

- **范围**：勾了预览范围就用预览范围，否则用场景渲染范围（跟 Blender 自己那一套一致，
  插件不造第三个范围概念）；
- **构建期间锁交互**（Vegas 行为）：只能看着播放头扫、预览窗跟着动；**`Esc` 中止，
  已构建的部分保留**；
- **每次按下都从零开始**：先把上一轮的成果连同 Blender 自己攒的 final 缓存一起清空；
- **改过东西就作废**：序列场景里任何改动都会让已构建内容整段失效——Blender 自己的
  失效是**部分的**（挪条带只清一部分、改名毫无反应），不能指望它；
- **装不下就"渲到哪里算哪里"**：水位顶到上限时自动收摊，报告/面板写明「内存已满：
  保留到第 N 帧」。保留的是**开头**这一段（实测 Blender 到顶后只是不再收新的，并不把
  先来的挤出去），有时还会因为 Blender 自带 prefetch 而多热一点，所以 N 是下界；
- **代价明写**：构建期间会临时接管 `use_cache_final` / `sync_mode` / `use_audio` 三项
  并在收摊时原样还原（**不碰**全局的 `memory_cache_limit`）；唯一例外是**你原本把本场景
  final 缓存关着**——那种情况下它会被留在打开状态并明确告诉你原因，否则刚装进去的画面
  会在还原的那一刻被清空。

插件**一根像素都不碰**：产物就是 Blender 自己的 VSE 缓存（同一条渲染＝预览＝导出管线）。
原理、备选方案与真机标定见
`docs/adr/0011-memory-preview-plays-the-range.md`。

### 切断素材（Split，`K`）

把一条**已经画了速度线**的素材一分为二：曲线被同一根切点竖线切开，**两半的并集与切
之前逐帧相同**——左半留下切点之前的部分、右半自切点开始，接缝两侧速度恒相等（不会凭空多出一个速度台阶）。

**切点就是播放头所在的那一帧**：`K` 按当前播放头切，播放头不在这条素材上时`K` 什么也不做（实测：条带 `1800..1900`、播放头 `2100` → op 直接 `CANCELLED`，一刀不切）。所以先摆好播放头，再按 `K`。

- 切点落在某一段内部时，两半各自在切点处得到一个**继承该帧原有曲线值**的端点；
- 切点落在**缓动段**（平滑 / 快速 / 慢速）内部时，被劈开的那一段在两半里**逐帧展开**
  ——"半个 S 形"不在四档里，硬套任何一档都会把形状改掉，而实际播出来的速度是按绝对
  帧逐帧算的，两边一旦分家就是"线看到的"≠"听到的"；
- 曲线末点本就在切点之前时，右半就是那条延长线的水平段；
- 这个修复**只发生在内存里**：切断之后**模型载荷**一个字都不动（监听器也不写，见下一条；
  承载层的对齐与映射表重建照旧，那是派生状态），
  所以切断本身**始终是一步撤销**。等到你**真正编辑**其中一半（拖个点 / 删个点）时，
  整组会顺带物化——每半各自成为自描述的切片，从此互不牵连。
- **v1.6.5 修的病**：切完那一刻右半会变成前半段的复制、要按一次 `Ctrl+Z` 才好
  （那一步撤销的其实是一次隐形写回，第二次 `Ctrl+Z` 才撤回切断）。原因是监听器
  在切完后替左半写了盘，擦掉了划分的指纹。现在切断之后**不写模型载荷**。
- 代价（明写）：切断后**立刻存盘退出**，文件里留的是旧数字；重新打开时会算出同一个
  结果，不会跑偏。切断后若把另一半删掉，剩下那半会退回老规矩（按条带长度收拢）。
- **v1.4.0 之前画的曲线**：先在**速度线上拖动任意一个点**再切，才走上面的新语义——
  拖动会让插件顺带补写载荷的声明区间（新语义的判据就靠它）。注意**挪条带位置不算**：
  那是 Blender 原生操作，不经插件，什么都不会写。不拖直接切，仍按老规矩读。

### 四档段曲线类型各自是什么形状

档名说的是**「变化集中在段的哪一端」**，跟这段是升是降无关：

| 档 | 形状 | 上升段（100%→300%） | 下降段（300%→100%） |
|---|---|---|---|
| 线性 | 匀速变 | 直线 | 直线 |
| 平滑 | 两端平缓、变化集中在中间 | S 形 | S 形 |
| 快速 | **起步急促、收尾平缓** | 上凸 | 下凸 |
| 慢速 | **起步平缓、收尾急促** | 下凸 | 上凸 |

所以同一个「快速」，小变大时上凸、大变小下凸——**两种情况是同一个形状**。拿凸向当判据会看成"两个选项标反了"（真发生过一次，见 `docs/adr/0006-curve-type-names-describe-the-start.md`）。

**没有键盘删点键位**：菜单打开期间键位表停摆，删点只走菜单项点击；`X` 留给原生"删除条带"。

显示：黄色速度线 + 白色 1.0x 基线 + 橙色方块速度点 + 速度百分比（**出厂不勾选**，见下）。

显示范围上限在面板设置里二选一：**`0 ~ 3.0x`（出厂）或 `0 ~ 10.0x`**（标尺满量程铺满
**条带绘制区**——Blender 画素材主体的矩形，上下各收回通道高度的 5%；本插件在其底部
**再让出 4% 通道高**的留白，让整条曲线看着略扁、最低速线不糊在素材下缘，见
`docs/adr/0010-speed-scale-fills-strip-draw-extent.md`）。出厂 3.0x 时 `1.0x` 落在标尺
**1/3** 处，上限速度的线正好贴住素材上缘。改上限**不动已有数据**：
曲线照旧存全量速度，只在下一次拖动时按新上限截住。

### 新建曲线的默认形状（面板下拉）

侧边栏面板里有「**新建曲线 › 默认段曲线类型**」下拉，四档与右键段菜单同一套档名，
**出厂值 = 平滑**（复刻 Vegas 的开箱行为：新条带第一次拖端点拖出来就是 S 形成型；
想要直线倾斜就把下拉掰回「线性」）。

它**只在曲线诞生那一刻读一次**——即你第一次按住一条还没有速度曲线的条带时：

- 已经建过曲线的条带，段类型**一个不动**；改下拉**不回溯**既有曲线；
- **拆段**（双击插点）仍继承原段类型、**并段**（删点/吞点）仍取左段类型，
  都不受它影响；
- 旧 `.blend` 里没有段类型属性的老曲线，读回仍是**全线性**（不因默认是平滑而
  变形——默认是"诞生值"不是"兜底值"）。

新曲线的两端都是 1.0x，所以那一刻档位看不出来：线性与平滑画出来是同一条水平线，
它第一次显形就是你**拖其中一个端点**的那一刻。见
`docs/adr/0007-default-segment-type-read-once.md`。

### 速度百分比什么时候出现

- **勾选**「显示 › 显示速度百分比」→ 每个速度点旁常显百分比；
- **不勾选（出厂）**→ 平日没有数字；**拖动中临时显示"本次正在改变的那些点"**：
  拖点显示那一个、拖某段线显示这一段的两端、拖尾段延长线显示末点。按下即出现，
  松开左键（或 Esc / 右键结束拖动）立刻消失。

拖动期间面板的绘制诊断行会写 `临时 n点`（`%TEMP%\seqvel_trace.log` 里也有留痕）——
"数字其实没冒出来"这类问题得能被查出来。见
`docs/adr/0005-direct-manipulation-no-edit-session.md` 修订 R10。

## 结果落地

- 每条目标条带对应**一条** `SPD_` 效果条带（`SpeedControlStrip`），按 `input_1`
  绑定去重（改名字也不会重复建）。
- 承载条带自动对齐目标：通道 = 目标 + 1、位置与长度跟随目标区间（效果条带本身也会
  跟随输入条带的时间范围）。
- 模式 `speed_control='MULTIPLY'` + `use_frame_interpolate=False`（**永不混合帧**，见 `docs/adr/0001-never-blend-frames.md`）。
- 关键帧插值写 **LINEAR**；影子模型按**段类型**采样后再写帧（缓动段逐帧写、线性段只写两端点；
  **两端速度相等的缓动段也只写两端点**——恒速时任何缓动都是常数，逐帧写与两端点写在数学上等价）
  —— 画出来的线就是实际速度（所见即所得）。
- 写入前对输入条带执行 **Retiming 重置**（重置重建策略），避免与原生 Retiming 叠乘。
  仅在条带**确实带原生 Retiming 数据**时才动手。
- 曲线持久化在条带的自定义属性 `seqvel_curve` 上，随 `.blend` 保存，重开文件不丢。

## 边界与已知限制

- **音频**：Speed Control 只处理画面，音频不变速也不变调；音频条带会被拒绝编辑并给出提示。
- **帧采样分两种，面板常显当前是哪种**：
  - **场景条带 → 子帧渲染（无级变速）**：小数源位置原样交给渲染器
    （`RE_RenderFrame(..., subframe)`），源时间连续，速度再低也不卡顿、也不重影。
  - **movie / image / movieclip → 取整选帧**：渲染前把源位置取整到最近帧，所以非整数倍速
    会有重复帧或跳帧（与原生 Retiming 同构）。
- **混合帧（相邻帧交叉淡化）刻意不做**：它只是把 `floor`/`ceil` 两帧按小数权重叠起来，观感就是
  重影；对场景素材更是纯损失（先丢掉子帧精度，再加一层重影）。真要"平滑且不重影"得靠运动矢量
  重采样（光流），Speed Control 不做。
- **场景素材"掉帧"是上游缺陷，不是插件坏**：Blender 的源图缓存（Raw cache）建键前会把时间
  取整，而 Speed Control 恰好把小数源位置放在被取整的位置上（原生 Retiming 的小数产生在
  取整之后，所以不受影响）。面板此时会显示「无级受限」并给一键开关——关掉本场景 Raw 缓存
  即恢复无级。证据与代码位置：`research/source-image-cache-subframe.md`、
  `docs/adr/0002-speed-carrier-despite-raw-cache.md`。
- 首点固定在素材起点，**不可删除**（速度线必须覆盖素材开头）。
- **音频明确不生效**：不做保音高（`pitch_correction` / Retiming 音频路径），纯音频条带被拒绝编辑，
  含音轨的条带变速时音频保持原样。这是决定，不是待办。
- 反向播放（负速度）、多选批量、插件上架：v1 不做（承载机制已支持负值）。
- 段曲线类型只有**四档**（线性 / 平滑 / 快速 / 慢速），**没有**可调「平滑量」的滑杆，
  也不支持框选多段批量改类型。拆段继承原类型、并段取左段类型（**新建**曲线的段取面板里
  那个默认档，出厂平滑）。

## 面板

侧边栏标签叫 **Velocity**（只留英文，Blender 不支持运行时改标签）。面板是唯一的
信息出口，**自上而下**：设置在前、诊断垫底——

1. **语言**：`English / 中文` 二选一，**出厂 English**。它存在插件偏好里（用户属性
   不是工程属性），跨 `.blend` 持久；切换即时生效，覆盖面板文案、右键菜单
   （含段菜单四档档名）、提示与报告（运行层）。**注册期固定**的文案
   （侧栏标签 `Velocity`、菜单标题、操作符与设置的悬停说明）Blender 不允许
   运行时切换，**常驻英中双语**；仅侧栏标签按用户要求只留英文。
2. **设置**：**显示**（编辑时隐藏原生 Retiming 显示、显示速度百分比）与
   **新建曲线**（默认段曲线类型、**显示范围上限** 300% / 1000% 二档）。
3. **目标条带**：活动条带（优先活动条带，其次选中的源条带）与删除按钮；没有可用
   目标时面板会说明原因（场景里有多少条带、选中几条、活动条带是谁），不会只显示
   「（无）」；读取条带列表/活动条带失败时会把异常原文写出来（不静默吞掉）。
   选中音频/效果条带等不可编辑的条带时，面板会直接写明原因。
4. **内存预览**：这一段的范围（含来源：预览范围 / 场景范围）、大概要占多少 MB 与
   当前上限、以及现在手上有什么（未构建 / 构建中百分比 / 已构建到第几帧与缓存体积 /
   内存已满 / 提前停止 / 已失效 / 中止）。
5. **状态警告**：编辑/音频提示、场景素材不匹配、子帧受限等。
6. **调试区（最下）**：编辑中常显 `时间轴区域 <尺寸> · 命中 <结果>`（用来一眼分清
   "根本没命中"还是"命中了却没动"）、承载条带现状、段类型分布、版本号。

承载绑定的输入是场景素材时，面板还会常显本场景 Raw 缓存状态：子帧被它吞掉时显示
「无级受限」并给一键开关（点了才改，可再点恢复）。

## 开发

分层（不要跨层绕行）：

```
seqvel/curve.py        纯 Python 影子模型（唯一事实源，零 bpy）
seqvel/geometry.py     条带坐标换算与命中检测（纯 Python）
seqvel/rules.py        条带类型规则（纯 Python）
seqvel/regions.py      定位时间轴区域（纯 Python）—— context.region 不可信
seqvel/editing.py      交互原语：双击检测、右键目标（纯 Python）
seqvel/ram.py         内存预览的规则层（范围 / 内存账 / 水位判定，零 bpy）
seqvel/store.py        模型缓存与持久化（条带自定义属性）
seqvel/carrier.py      落地映射：Speed Control + speed_factor 关键帧
seqvel/watch.py        条带区间监听：末端跟随 / 吞点、承载重落地（映射表重建）、内存预览失效（ADR-0004 修订 R1）
seqvel/preview.py      内存预览的构建 operator（Shift+B，ADR-0011）
seqvel/overlay.py      绘制 overlay（draw handler + gpu/blf）
seqvel/hover.py        悬停光标（MOUSEMOVE 键位 → HAND_POINT）
seqvel/interaction.py  直接操纵的 modal 操作与点/段菜单
seqvel/status.py       运行状态（面板文案与诊断的单一出口）
seqvel/ui.py           侧边栏面板与设置
```

`curve` / `geometry` / `rules` / `regions` / `editing` / `ram` 是零 bpy 层，`store` / `watch`
自带 `try: import bpy` 兜底——所以「快跑」那条命令能直接把这几层跑起来。对应的硬约束是
`seqvel/__init__.py` **模块级不得裸碰 bpy**（连装饰器也不行），否则纯 Python 下连
`import seqvel` 都过不去；挂 app handler 的 `persistent` 统一在 `register()` 期套。

### 坑位：不要用 `context.region.view2d` 做命中检测

三条入口（面板按钮 / `Alt+S` / 工具栏工具）**已随 ADR-0005 一起移除**，但这条坑位仍然有效：
`context.region` 只会被"事件派发给哪个区域"决定，而 `bpy.ops` 直调（脚本、测试、F3 面板）
拿到的可能是任何区域。当年三条入口的 `context.region` 分别是侧栏 `UI`（面板按钮、面板上的
`Alt+S`）与 `TOOLS`（工具栏按钮），**没有一个是时间轴**。真机实测（5.2.1）：

- **所有**区域类型的 `region.view2d` 都不是 `None`（`HEADER` / `UI` / `TOOLS` /
  `CHANNELS` / `FOOTER` / `PREVIEW` 全都有，连 1x1 的折叠区域也有），所以
  "拿不到 view2d 就放弃"这种防御永远不会触发；
- 但只有 `WINDOW`（时间轴）那个的坐标系是"帧 / 通道"。同一个鼠标像素、同一条曲线：

  | view2d 来源 | 命中结果 | `region_to_view(鼠标)` |
  |---|---|---|
  | `WINDOW` | `Hit(SEGMENT, 0)` ✓ | (94.26, 5.50) |
  | `UI` | `Hit(NONE)` | (nan, nan) |
  | `TOOLS` / `CHANNELS` | `Hit(NONE)` | (46.8, −266.4) |

- 合起来就是"速度线画得出来（绘制走 `WINDOW/POST_PIXEL` 回调，region 必然正确），
  但怎么点都没反应（命中用的 view2d 是错的）"。

因此命中与坐标换算一律经 `regions` 显式定位时间轴 `WINDOW` 区域；鼠标位置由
`event.mouse_x/y` 减去该区域的 `x/y` 得到（二者同为**窗口绝对**坐标），而不是直接用
`event.mouse_region_*`（那是"事件被交给的那个区域"的局部坐标）。编辑器里编辑时面板会
常显 `时间轴区域 … · 命中 …`，就是给这件事做的自查出口。
