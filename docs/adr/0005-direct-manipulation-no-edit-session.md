# 直接操纵取代模态编辑会话

## Status

accepted

## 背景

速度线编辑原先是模态会话：从工具栏工具 / 面板按钮 / `Alt+S` 三条入口进入
`SEQVEL_OT_edit_speedline` 的 modal，会话存续期间**吞掉一切事件**（只放行
中键/滚轮导航）。代价是编辑中无法做任何原生操作——空格不能播放预览、点
空白不能移动播放头、不能顺手选别的条带；"进入/退出模式"本身也是一层无谓
的心智负担。

原型 v0.4.2 早已验证过第三条入口（工具栏工具）的行为：按在速度线上直接开
拖、按在空白处原样 `PASS_THROUGH`。也就是说"免会话直接拖"的机制已存在，
只是被锁在"工具必须先激活"后面。

## 决定

1. **直接操纵，无编辑会话**：把工具路径推广成常驻行为。在 VSE 时间轴上
   按下时先做命中检测：按在**可见**的速度线/速度点/尾段延长线上 → 启动
   一个随松手结束的短 modal 完成拖动；没按中 → 一律 `PASS_THROUGH`，原生
   选择、框选、空格播放、移动播放头从不被打断。不存在"进入/退出编辑模式"。
2. **命中边界 = 所见即可抓**：常开显示建过速度曲线的条带（没建过的条带仅
   选中/活动时显示默认线）；命中集合与显示集合完全一致——**不存在看不见
   却能抓住的线**，空白点击永远不会被隐形线吃掉。同屏多条线重叠时取鼠标
   最近者。
3. **拖动开始时隐式选中**：按住某条线的瞬间把该条带设为选中/活动（拖动
   吃掉的正是这次点击，原生选中不会发生；不补选则面板"活动条带"、原生
   高亮、速度线三者指向脱节）。
4. **右键按命中分流**：右键按在速度点上 → 弹出自定义点菜单（鼠标位置，
   第一版只有「删除点」，菜单内快捷键 `D`）；没按在点上 → `PASS_THROUGH`
   交还原生右键。**不注册任何键盘删点键位**：`X` 必须留给原生"删除条带"，
   删除一律走点菜单（或其菜单快捷键）。
5. **撤销按动作**：无会话后每次拖动/插点/删除天然是独立的一步撤销
   （原"整个会话一步"随之废弃；逐动作撤销本就是 v1.1 计划项，此处提前落地）。
6. **三个旧入口移除**：工具栏「速度线」工具、面板「编辑」按钮、`Alt+S`
   全部删除——它们与常驻直接操纵完全重复。面板只做信息出口，常驻提示
   "直接按住速度线拖动"。
7. **无悬浮高亮**：不做鼠标悬停命中反馈（无会话时拿不到 MOUSEMOVE），
   依靠"所见即可抓"保证按下去必然有反应。

## 考虑过的选项

- **保留会话 + 定向穿透（方案乙）**：会话内放行空格与未命中的左键——改动
  最小，但"模式"心智负担不变，press/release 穿透的边界情况多。用户仅因
  "右键删点可能和原生菜单打架"才考虑它；命中分流方案证实可行后放弃。
- **键盘 Delete/X 删点**：`X` 与原生"删除条带"打架，必须放弃；`Delete`
  与点菜单快捷键 `D` 重复，不注册（`D` 已按用户定案实现为"右键选点后
  快捷删除"，无目标即穿透）。

## 修订（真机反馈，2026-09-15，v1.2.1）

v1.2.0 首轮真机暴露的问题对上文三点做了修订；被修订的原文保留存档：

- **R1（修订决定 3）隐式选中取消**：拖动不再设置条带的选择/活动态——
  Vegas 式"拖包络不选素材"。已核实拖动链路（命中、拖动、落盘、HUD）无
  任何选中依赖，全库唯一在拖动路径上设置选中的就是被删除的
  `_select_implicitly`。代价：面板"活动条带"栏在拖动时与编辑对象脱节，
  由头部"速度线拖动中 — 条带名"提示兜底。
- **R2（修订决定 4）`D` 键移除**：弹窗菜单打开期间键位表停摆（菜单接管
  全部按键），"菜单开着按 D"只能依赖 Blender 的菜单加速键机制，对插件
  自建键位不可靠（真机无效）。删除统一走点菜单项点击。
- **R3（修订决定 7）悬停光标加入**：Blender 无悬停事件，且
  `bpy.types.Window` **没有 `mouse_x`/`mouse_y`**（5.2.1 RNA 实测），
  定时器轮询无从谈起（v1.2.1 的定时器方案因此从未生效）。v1.2.2 起改用
  **MOUSEMOVE 键位驱动**：把悬停 operator 绑到 Sequencer 的 `MOUSEMOVE`，
  每次移动做一次命中检测后**一律 PASS_THROUGH**（旁观者铁律），命中时切
  `HAND_POINT`（指向手指，5.2 枚举实测存在），离开恢复 `DEFAULT`。
  已知边界：鼠标离开时间轴区域后该 operator 不再被唤醒，HAND_POINT 保留
  到下次进入时间轴（全局 MOUSEMOVE 键位成本大于收益，先接受）。
  另：想给拖动加 `TWEAK_L` 键位兜底也不可行——5.2.1 的
  `keymap_items.new` 拒绝 TWEAK_L/EVT_TWEAK_L（枚举里没有，实测）。
  键位注册必须逐项容错 + 注册前清残留：一项抛异常曾中断整批，键位项
  跨注册累积（v1.2.2 实测修复）。
- **R4（实现教训，非决定）拖动期间的事件消费策略**：按下瞬间的穿透纪律
  （未命中 `PASS_THROUGH`）**不适用于拖动过程中**——modal 兜底必须
  `RUNNING_MODAL`（吞掉一切），只显式放行导航与空格。v1.2.0 把兜底写成
  `PASS_THROUGH`，导致按住拖动时 TWEAK 类事件漏给原生键位，原生开始拖
  条带（恰被隐式选中过）、曲线冻住——真机表现为"一拖线就变成拖素材"。
  键位注册同时加 `head=True` 保证优先级。

## 修订（段曲线类型，2026-09-15，v1.2.7）

- **R5（修订决定 4）右键命中集合从"点"扩到"线的某一段"**：段曲线类型
  （线性 / 平滑 / 快速 / 慢速，见 `CONTEXT.md`「段曲线类型」）是**段**的
  属性，而屏幕上没有任何一个"点"能代表某一段，所以决定 4 的分流扩成三路：
  命中**速度点** → 弹点菜单（原样，第一版只有「删除点」）；命中**线的某
  一段** → 弹段类型菜单（四档、当前档打勾、不设平滑度滑杆）；其余（含末点
  右侧的水平延长线 `HIT_TAIL`）→ 一律 `PASS_THROUGH` 交还原生右键。
  决定 4 的其余部分不变：仍**不注册任何删点 / 改类型的键位**，一切走菜单。
  - **不新开 ADR**：这是命中集合的扩张，不是交互模型的改变。
  - 代价：速度线附近那条窄带里不再出原生右键菜单（已接受）。
  - 命中判定吃的是**与绘制同源的采样**（`geometry.sample_step` 定步长、
    `Curve.sampled_points` 出采样）。不加这一条，"平滑段画出来是弯的、
    弯的地方却抓不到"就会以新形式复发——那正是决定 2「所见即可抓」要防的。
  - 没有曲线时照样弹：屏幕上那条默认 1.0x 直线就是"唯一的一段"，不先建
    模型也能直接把它设成平滑（否则又破一次决定 2）。

## 修订补记（真机排障，v1.2.4–v1.2.6）

下面三条此前只活在代码注释与回归测试里，没有回填本 ADR。补记是为了让
"R6 / R7 / R8"这些在代码里到处出现的编号有据可查，也免得后来者把真机
换来的铁律当成可以随手改掉的写法。

（编号与时间不同序：原 R5 是 v1.2.5 的"松手后吞咬窗口"，被 R7 推翻后该
编号即退役，v1.2.7 复用给上面的段菜单。）

- **R6（收尾决定 3）"按下即翻转"的回收规则**：按下速度线时，原生层会
  **先**把该条带选中 / 激活，才轮到插件的键位求值——所以 R1 的"拖动不碰
  选择态"必须补一手回收，否则拖完线素材莫名被选上。回收条件严格限定为
  "选中集合 ⊆ 按下前快照 ∪ {本条带}，或 active 恰好翻成本条带"；基准取
  hover 常驻缓存的**按下前**最后一次 mousemove 快照（按下瞬间原生层已经
  翻转，invoke 里现抓必定晚一步）。用户自己的选择绝不碰。
- **R7（实现铁律）松手必须 `FINISHED`**：`PASS_THROUGH` **不会结束 modal**。
  v1.2.5 用"松手后再吞咬 0.3s"收摊，结果 operator 变僵尸：后续 mousemove
  全被吞进拖动分支（真机表现 = 时间线冻结，要狂敲 ESC 才出来），且冻结期
  松手还会命中 RELEASE 分支给它续命。改为松手立刻 `FINISHED`；松手后可能
  到达的合成 CLICK 造成的选中翻转，交给 `bpy.app.timers` 一次性任务
  （0.15s）按 R6 规则延迟回收。**收摊路径一律 `FINISHED`。**
- **R8（键位求值顺序）工具键位表先于编辑器键位表**：5.2.1 实测，活动工具的
  键位表（如 "Sequencer Tool: Select Box"）**优先于**编辑器键位表求值。按在
  **已选中**条带上时，原生 `sequencer.select` 以模态启动（`deselect_all=1`、
  `wait_to_deselect_others=1`）先吃掉 PRESS——给插件项插 "Sequencer" 表头
  也没用。插件编辑项因此同时注册进工具键位表表头（含兜底表），未命中照旧
  `PASS_THROUGH`，原生行为不受影响；`load_post` 自愈重挂一次
  （工具键位表可能晚于插件注册才存在）。

## 修订（Ctrl 微调拖动，2026-09-16，v1.2.9）

- **R9（决定 2 的修饰，不改交互模型）按住 Ctrl = 微调拖动**：拖动链路三种
  目标（点 / 段 / 尾段）全部支持；只作用在**增量**上——速度变化量是常规的
  0.5 倍（光标位移 delta × 0.5），刻意**不做**固定步进吸附（不引入新常量），
  钳制仍走 ``[SPEED_MIN, SPEED_MAX]``。
  - **点拖在微调下从"绝对吸附"改为"锚定式"**：1:1 拖动保持"速度 = 光标
    速度"不变；微调时改为 ``点速度 = 冻结生效时点的速度 + 0.5 × (光标速度
    − 生效瞬间的光标速度)``——与段拖的快照锚定**同构**，生效瞬间零跳变。
    同时**冻结帧**：只沿 Y 移动，帧停在生效那一刻的值。
  - **段拖 / 尾段拖本就只改速度**（快照锚定只作用在速度分量上），对它们
    Ctrl 只贡献减半——"仅 Y 轴"对这两种模式不是新约束而是既有事实。
  - **修饰键实时开关**（按住 = 微调、松开 = 1:1）：每次开 / 关的瞬间
    **重新锚定**（快照 = 当前值、锚 = 当前光标速度），切换零跳变。点拖解除
    冻结时帧恢复 1:1 跟随光标——跳到光标当前帧属预期（冻结期间光标在
    x 方向走过的路不回放）。
  - **Ctrl 只修饰已在拖动中的动作**：命中检测、按下分流（R5 的三路）、
    悬停光标（R3）、双击插点一概不变；微调中的拖动仍是"拖动期间吞事件、
    只放行导航与空格"（R4），收摊仍一律 `FINISHED`（R7）。一次拖动无论
    开关多少次记**一步撤销**（"撤销按动作"不变）。
  - **键位代价**：Blender 键位表对修饰键有匹配优先级，Ctrl+按下会被原生
    同键项截走，所以编辑项需要 **ctrl=True 变体**，与 R8 同款纪律注册
    （编辑器表 + 工具表表头 + `load_post` 自愈重挂）。
  - 头部横幅在微调生效时显示"微调 ×0.5"后缀（"不静默"纪律的最小满足）。

## 修订（拖动临时读数，2026-09-16，v1.3.0）

- **R10（决定 2 的反馈补丁，不改交互模型）未勾选「显示速度百分比」时，拖动中临时
  显示被改变的点的百分比**。勾选态原本是"全部点常显"，未勾选则是全无数字反馈；
  而未勾选恰恰是日常状态（出厂默认即不勾），拖动时看不到数值等于"看不见自己在改
  成什么"。
  - **集合 = 本次拖动正在改变的那些点**：点拖 = 被拖的那一个；段拖 = 该段的**两个
    端点**（决定 2 的段拖本就是两端同步平移）；尾段拖 = 末点（尾段延长线只有一个
    会动的端）。
  - **窗口 = 按下命中那一刻 → 松手 / Esc / 右键收摊为止**，收摊即消失。**不做**
    "必须移动过才显示"：按下即算激活。
  - **只对被拖的那一条条带生效**：同屏其它可见条带照旧不显示（未勾选 = 不显示）。
  - **勾选时的语义一字不改**：勾上 = 全部点常显，此时临时机制被完全覆盖；**不做
    第三态**（例如"勾选但只显示当前段"）。
  - **样式与常显 HUD 完全一致**（同字体、同位置、同透明度），不引入第二套视觉——
    否则会出现"两种百分比看起来不一样"的新问题。
  - **实测坑：松手路径里有一条既不落盘也不重绘的**（按下没拖动 → 只判双击插点，
    不走 `_persist` 里那次重绘）。"松手即隐藏"因此不能搭落盘那次重绘的顺风车，
    收摊时必须自己补一次重绘，否则数字会赖到下一次自然重绘才消失。
  - **不静默**：本次绘制临时显形了哪几个点，写进绘制诊断（面板常驻那行「绘制回调
    n 次 · …」的串尾 + `seqvel_trace.log`）。全屏文字 HUD 读不了像素——不记账，
    "数字其实没冒出来"这类回归在真机上无从证明。

## 修订（锚定输入去饱和，2026-09-16，v1.5.3）

- **R11（决定 2 的输入语义修正，不改交互模型）锚定会话（R9）的输入不再在
  显示范围边界饱和**。用户实测体感：点在 12% 处按住 Ctrl 往下拖，只能挪到
  ≈7% 就"挪不动"，往上却很自由；越靠近标尺边界越受限、靠近通道中心越自由。
  - **根因**：光标→速度映射 ``yfrac_to_speed`` 把"一个通道高度"线性铺满
    ``[SPEED_MIN, cap]`` 并**钳制**（"标尺"语义，绝对吸附与插点路径要的正是
    它）；R9 的锚定会话把这个**钳制后的绝对位置**当相对输入——增量
    ``0.5 × (钳后光标 − 钳后锚点)`` 在光标贴边时饱和，点行程 = 0.5 ×
    （锚点到"摇杆边界"的距离）。0.5 增益把"墙"暴露成"沼泽"：光标贴边了、
    点才走了一半。非微调路径没有此问题（点=光标值，视觉一致）；段/尾拖
    1:1 时同样饱和但不可见。
  - **修正**：锚定会话改吃**未钳光标值**（``yfrac_to_speed_raw``，同一条
    线性标尺、同一换算率，下沿以下为负、上沿以上超 cap；``SegmentDrag``
    的锚点与 ``apply`` 输入同步去钳）。增量因此在光标越界后**继续增长**，
    点一路走到**值域边界**才停——边界是唯一的墙，且与非微调拖动是同一条
    （想超过 3.0 先切 1000% 档，微调不成为突破显示档的特例）。
  - **不变量**：条带内手感逐值不变（raw 与钳制版在标尺内一致）；非微调
    路径一字不改——绝对吸附点拖的光标值在交互层显式钳回当前档
    （``move_point`` 只钳数据硬顶，不能靠它兜显示档）；1:1 会话的可见
    结果与旧实现逐值一致；``FINE_SCALE=0.5`` 不变；值域钳制仍由
    ``clamp_speed(快照 + delta, cap)`` 收口。
  - **判据**（语义用例，先在旧码上转红复现 12%→7%）：光标越界后增量继续
    增长、点停在 ``[SPEED_MIN, cap]``；界外重锚零跳变；1:1 会话照样落到
    值域边界。

## 后人不该"简化"回去的理由

"加一个编辑模式把事件全收进来"是交互上省事的写法，但那正是本 ADR 移除的
东西：用户在编辑中失去预览与选择能力。若有人想恢复会话（例如为了"一步
撤销整段编辑"），必须同时恢复三条入口与面板状态机，属交互契约回退。
回归测试须覆盖：未命中点击必须 `PASS_THROUGH`（原生选中不失效）、命中才
起拖、拖动**不碰选择态**（R1 / R6）、右键点上弹点菜单 / 右键线上弹段菜单 /
其余穿透（R5）、常开显示与命中集合一致、Ctrl 微调（R9）：增量减半、点拖
帧冻结、实时开关重锚零跳变、撤销仍是一步、拖动临时读数（R10）：集合只含
本次被改变的点、只作用于被拖的那条、收摊即隐藏（含没拖动的单击路径）、
锚定输入去饱和（R11）：光标越界后增量继续增长、点停在值域边界、界外重锚
零跳变、1:1 可见结果不变。
