# 英文优先的双语界面：语言模式存偏好，静态层永久英文

插件要服务非中文用户，面板/菜单/提示需要 en/zh 双语，且**默认 en**。决定：语言模式（`en`/`zh`）是**用户属性不是工程属性**，存 AddonPreferences（跨 .blend 持久），面板顶行提供切换。文案分两层：**运行层**（面板文字、右键菜单项、INFO/ERROR 报告、段类型档名、枚举项与设置项 tooltip）经字符串表 `T()` 在运行时切换；**静态层**（侧边栏标签、面板标题、operator 的 `bl_label`/`bl_description`、左下角按键提示）注册期固定，**整层英文化、永不切换**——Blender 不支持这些字段运行时换语言，唯一替代"注销重注册所有类"会抖动面板指针与 keymap、并重置已有设置，代价不可接受。

**代价（刻意接受）**：zh 模式下静态层仍是英文（F3 搜到的是英文 operator 名、operator tooltip 是英文）。三个设置项为拿到双语 tooltip，从 `BoolProperty` 改为**动态枚举**（Blender 只允许枚举的名称/说明走运行时回调）——旧 .blend 读回时这两项设置会被重置一次，属接受的一次性迁移成本。

**修订 R1（v1.5.1）：静态层用户可见文案＝常驻英中双语。** v1.5.0 交付后用户实测发现：注册期固定的那批文案里，设置项悬停说明（属性 `description`）是英文、而菜单/操作符的 `bl_label`/`bl_description` 漏改还是中文——中英混杂且两处口径不一。裁定：凡是**注册期固定、用户看得见**的字段（菜单标题、operator 的 `bl_label`/`bl_description`、设置项悬停说明），一律写成"English 中文"双语常驻（zh/en 模式同串）；只有**无语义的注册串**（操作符 idname、键位提示里的按键名）保持纯英文。理由：这批字段永远切不了，双语是唯一让两类用户都看得懂的形态；字符串变长是可接受的代价。**动态枚举项不在其列**——它们走运行时回调，能实时切换，维持纯单语（en 模式纯英文、zh 模式纯中文），不做双语。此修订同时修正"静态层永久英文"的原口径；运行层纪律（新文案必须进字符串表、源串英文）不变。

**修订 R2（v1.5.2）：枚举项级 description 清空，tooltip 由属性级双语说明独自承担。** v1.5.1 交付后用户实测发现设置项 tooltip 出现"英中英/英中中"重复。根因有二：① Blender 枚举属性的 tooltip＝属性级 `description`＋当前选中项的**项级 description** 两段拼接，两层各维护了一份文案；② 项级说明走 **RNA 缓存**，切语言不保证触发回调重算（同机实锤：下拉项名称残留切换前语言）。裁定：枚举项 items 回调只返回二元组（identifier, name），**不再返回 description**；tooltip 一律由注册期双语属性说明承担（静态、双语、长串不命中 Blender 自带翻译词典）。代价：下拉展开后悬停单行不再有独立 tooltip（行名一两个词，可接受）。另实测旁证：用户开启 Blender 界面翻译（zh_HANS）时，运行层英文串会被其自带词典按上下文改写（如 `Operator` 上下文 `Smooth→光滑`、`Delete Point→删除点`）——这不是插件缺陷，关闭界面翻译即愈；但选型时新增串应尽量整串化、避免恰好命中词典的常见词。

**Consequences**：字符串必须集中在字符串表模块、源串一律英文；新增用户可见文案不许硬编码中文；注册期字段的新增/修改必须检查是否需要双语常驻；枚举项禁止携带项级 description；`SPEED_MAX` 从常量升格为场景设置（见「显示范围上限」），曲线模型仍存绝对速度值，不依赖上限。
